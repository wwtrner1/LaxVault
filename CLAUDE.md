## What this is

LaxVault: a lacrosse practice planner and diagram tool for volunteer youth and high-school coaches. Vite + React 19 SPA, a single Netlify Function as the API, Netlify Database (Postgres) via Drizzle, Netlify Identity for auth, deployed on Netlify. It needs its own Netlify site, Identity, database, Stripe products and Twilio Verify sender; do not reuse GridIronVault's.

## Commands

```bash
npm ci                 # install
npm run dev            # Vite dev server (frontend only — /api and Identity are not served)
netlify dev            # full stack locally: Vite + functions + Identity (needs Netlify CLI + linked site)
npm run build          # production build to dist/
npx tsc -p .           # typecheck (tsconfig has noEmit; there is no lint or test script)
```

There is no test suite, linter, or formatter configured. `npx tsc -p .` and `npm run build` are the checks to run before pushing; the `Checks` workflow (`.github/workflows/ci.yml`) runs both on every PR.

## Architecture

### Local-first data, cloud when signed in
- `src/lib/store.ts` is the app's source of truth: a hand-rolled external store (`useSyncExternalStore`) persisted to `localStorage` under `snapline.workspace.v1`, holding plays and playbooks.
- Every save writes to the local store first, then — only if signed in — calls the API and replaces the local record with the server copy (`toStoredPlay`, `remote: true`). Signed-out coaches keep working entirely in the browser. See the save flow in `src/pages/Builder.tsx`.
- `store.mergeRemotePlays` reconciles server rows by `updatedAt` (newer wins).
- Other per-browser stores: `tier.ts` (`nextplay.tier.v1`), `track.ts` (`nextplay.events.v1`), `autofill.ts` (`nextplay.autofill.v1`).

### API (`netlify/functions/api.ts`)
- One function mounted at `/api/*`, hand-routed by path segments `[resource, id, action]`. Resources: `me`, `plays` (incl. `POST plays/:id/copy`), `playbooks` (incl. `POST playbooks/:id/plays`), `call-sheets`, .
- `PUT /api/plays/:id` only writes the fields it is sent (`sanitisePlayPatch`), so scene-only updates from bulk edits keep the play's name and tags.
- Auth comes from `getUser()` (`@netlify/identity`) server-side; writes are scoped with `ownerId = me.id` in the `WHERE` clause. `ensureProfile` upserts a `profiles` row on first write.
- Errors are returned as `{ error }` with coach-facing wording; `src/lib/api.ts` throws `data.error` so the UI can toast it directly.
- `track()` beacons to `/api/events`; the function stores the three known events for signed-in coaches (`events` table) and answers 204 to everything else.
- Client wrapper: `src/lib/api.ts`. Add a resource by adding a branch in the function and a method on `api`.

### Database
- Schema: `db/schema.ts` (Drizzle, Postgres). Client: `db/index.ts` uses `drizzle-orm/netlify-db` — no connection string in code.
- Migrations live in `netlify/database/migrations/` (drizzle-kit output dir). Change the schema, then `npm run db:generate`; never hand-edit generated migrations/snapshots.
- `plays.scene` is JSONB holding the whole editor document; its shape is the `Scene` type, not a DB schema.

### Play editor / scene model
- `src/lib/types.ts` defines `Scene` (`version: 2`, fixed `CANVAS_W`×`CANVAS_H` = 1040×660, `losY`, `nodes`) and the node union: `player | path | shape | text`, all sharing transform fields (x/y/rotation/scale/z/groupId/locked/hidden).
- One scene drives everything: the editor (`components/PlayCanvas.tsx`), thumbnails (`PlayThumb`), and exports. Shared SVG rendering is in `lib/render.tsx` (`NodeLayer`, `MarkerDefs`) and `lib/field.tsx` (field backgrounds per `FieldView`).
- `lib/scene.ts` — pure scene ops (selection, align/distribute/flip, cloning, node factories). Auto-connect paths store `fromId`/`toId`; call `reconcileConnections(scene)` before saving so they stay glued to their tokens.
- `lib/geometry.ts` — transforms and path-data math. `lib/tools.ts` — tool/mode definitions and export sizes. `lib/presets.ts` — position token colors and formation presets. 
- A fresh `/build` opens a blank Designer; the New Play setup wizard was removed in Phase 2d. `lib/fileNewPlay.ts` files a new play in the playbook it was started from (`?book=`).
- Side panels: on tablets and up the tools rail and the Selection/Play panel tuck against their edges from slim edge tabs (`.dz-edge` in `designer.css`); Ctrl+\ (or the field menu) hides or shows both. Remembered in `laxvault.panels.v1` (the right panel only on wide screens, where it docks). Call `showRail()`, not `setRailOpen(true)`, so a tucked rail comes back too. The field refits through the stage's ResizeObserver.
- First read: at most one `PathNode` per play has `firstRead: true`, always drawn in `FIRST_READ` (cyan-2) via `lineColor()`.
- Floating tools (`components/FloatingToolbar.tsx`): a draggable, collapsible mini-bar over the field (Select, Route, Dashed, Block, Text; 1st read / 2nd read / Checkdown / Defense colors; weights). It is a sibling of `.builder-stage` inside `.dz-stage-wrap`, never inside the canvas, so it can't swallow drawing. Picks restyle the selected lines or set the next line, through the same Builder state as the Style card. Its color row (the `PALETTE` swatches plus the full `ColorPicker`) colors whatever is selected (lines, player fills with their letters, labels) or the next line (`pickColor` in `Builder.tsx`), and its head carries Undo and Redo. Its spot, open state and dock live in `laxvault.floatbar.v1`; Home on the grip or the dock button puts it back in the corner.

- Top bar: brand, play name, Prev/Next, the work tabs, then zoom, Fit, Details, Run play, Export, Save and **Extras** (one drop-down, `#dz-more-menu`, sections Edit, Field, Play, Go to, Help). Undo/Redo, Clean up, Route depths, the field select, Field controls, More tools and Back to the Vault live in Extras now; a dot on the button shows while route depths are on. Below 760px Details/Run/Export move into it too (`is-wide-dup`), and below 900px the work tabs do (`is-tabs-dup`).

### Work tabs
- `components/WorkTabs.tsx` + `lib/workTabs.ts`: Designer · Playbook, in the Designer's top bar (`tone="dark"`). They are plain links carrying one context in `laxvault.worktabs.v1` (last play and playbook from the Designer): Playbook opens `/playbooks?book=`. In the Designer a tab saves unsaved changes first (`openFromTree`). The Practice planner joins them later.

### Plans and gating
- `src/lib/plan.ts` owns every entitlement (`TIERS`, `gateSave`, `gatePlaybook`, `gateSize`, `gateSheets`, `gateTool`, `canShare`, `cappedDpi`). UI and export both read gates from here — add new limits here, not in components. A `Gate` carries user-facing `reason`/`cta`. Tier ids (`free`, `solo` = Coach, `crew` = Staff) are kept from the football product so the Stripe price keys still map; the Program tier was removed (club admin is out of the MVP). **Prices (2026-10-29, Wes: aim for subscription volume at a low cost):** Coach $5/month or $39/year (yearly shown first), Staff $12/month or $99/year (head coach + 3 assistants), Season Pass $15 for four months, founding $29/year for life (beta coaches); Sideline free keeps 15 drills and plays. Set at or under the competitor anchors (about $5 solo, $18–33 team). A rerun of billing setup makes new prices and moves the lookup keys; old prices are never archived. They live in `plan.ts` (display) and `netlify/billing/setup.ts` (Stripe amounts); change both together. `assistantSeats` is display copy until live practice mode builds run-only assistant seats.
- The account's plan lives in `profiles.plan` (default `beta`) and the API enforces what it can see: Vault size and public copies (`plays`) and playbook count (`playbooks`), refusing with `{ code: "plan_limit" }` and the gate's own wording. `tier.ts` mirrors it in the browser (`syncPlan` after sign-in; `choosePlan` for the Account/Pricing pickers). During beta coaches switch plans themselves via `PUT /api/me/plan`; set `PLAN_SELF_SERVE=false` when billing takes over. Export sizes, sheets and locked tools happen in the browser, so they're client-side gates only.
- `lib/guard.ts` (`useCaptureGuard`) deters screenshots on paid diagrams; the real protection is watermark + DPI cap in `export.tsx`/`plan.ts`.

### Billing (Stripe)
- Sideline exports cap at 86 DPI (`maxDpi`, lowest DPI chip is 86). Browser prints on Sideline are blurred and tiled with a watermark: `useFreePrint` (`lib/guard.ts`, mounted in `App.tsx`) sets `data-free-print` on `<html>` and the `@media print` block at the end of `global.css` does the rest. Deterrent only.
- A subscription that Stripe reports `past_due` or `unpaid` drops the coach to Sideline immediately (`PAYING` in `applySubscription` is only `active`/`trialing`); a paid retry restores the plan.
- `netlify/billing/stripe.ts`: Checkout (`POST /api/billing/checkout {offer}`), the customer portal (`POST /api/billing/portal`) and the webhook (`POST /api/billing/webhook`, public, signature-checked, handled before the sign-in and phone checks). Off until `STRIPE_SECRET_KEY` and `STRIPE_PRICES` are set; `GET /api/me` returns `billing` and the browser (`useBilling`, `goToBilling` in `tier.ts`) then sends plan buttons to Stripe instead of the beta switcher.
- `netlify/billing/setup.ts`: `POST /api/admin/billing/setup` (owner only) creates the products and prices in Stripe from `STRIPE_ADMIN_KEY` (a restricted key, Products + Prices write only) and returns the ids ready for `STRIPE_PRICES`. Idempotent: prices carry `lookup_key` `laxvault_<offer>` and products `metadata.laxvault`, so a rerun reuses them. Delete `STRIPE_ADMIN_KEY` once the catalogue exists.
- `STRIPE_PRICES` is JSON mapping `solo_month`, `solo_year`, `season`, `crew_month`, `crew_year`, `founding` to Stripe price ids; amounts live in Stripe. Also `STRIPE_WEBHOOK_SECRET`. The webhook is the only writer of `profiles.plan` for paying coaches (`stripeCustomerId`, `stripeSubscriptionId`, `planEndsAt`). A Season Pass is a one-time payment that sets `planEndsAt` four months out; `planState` drops it to Sideline after that when no subscription is behind it. `founding` is refused unless the account's plan is still `beta`.

### Playbook sync
- Playbooks are local-first like plays but `src/lib/playbookSync.ts` (`PlaybookSync`, mounted in `App.tsx`) copies them to the account while signed in: sign-in pulls `GET /api/playbooks` (playbooks plus ordered member ids) and `store.mergeRemotePlaybooks` adds new ones and takes a cloud copy newer than the local one; every store change pushes a moment later (`POST /api/playbooks` once, then `PUT /api/playbooks/:id` with `playIds` replacing the whole list); `store.removePlaybook` deletes it from the account (clearing the local workspace does not). A local playbook keeps its own id and records the account's as `cloudId`; only UUID play ids (plays already on the account) are sent. Don't call `api.createPlaybook` from feature code, just write through the store. A play saved to the account gets a new id: use `store.replacePlayId` so it stays in its playbooks.

### Playbook tree
- `components/PlaybookTree.tsx` is the folder tree of playbooks (plus Unfiled) with their plays: counts, P/R/D/S badges, `+` for a new play in a folder (`/build?book=<id>`; `save()` in the Builder files the new play there), a new-playbook field, find box (over 8 plays), drag a play onto a folder to add it, and WAI-ARIA tree keys (arrows, Home/End, Enter, `*`). It sits in the Shell side menu and on the Designer's Plays tab (folder icon, `RAIL_GROUPS.plays`), where opening a play saves unsaved changes first. Open folders are remembered in `laxvault.tree.v1` (`lib/treeState.ts`); it reads and writes only through the store, so playbook sync carries every change.

### Phone check (Twilio Verify)
- `netlify/security/phone.ts`: a coach asked for a phone (`phoneNeeded` in `api.ts`) adds a verified mobile and a new device needs a texted code ("Confirm this device", `PhoneGate.tsx`). To keep text costs near zero, only a suspicious trial is asked by default: a coach on `trial` in a browser that already carried another coach's trial (browser fingerprints are `device` rows in `trial_claims`, the flag a `suspect` row that lasts while the trial does). `PHONE_CHECK=all` asks every account, as GridIronVault does. The check is on only while `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN` and `TWILIO_VERIFY_SID` are all set (and never on Deploy Previews). To switch it off, delete `TWILIO_VERIFY_SID` in Netlify and redeploy; coaches then sign in with no code. Env changes only reach the function on a new deploy.
- Twilio 20003 / 401 ("invalid username") means the Account SID and Auth Token in Netlify don't match the Twilio account (usually a rotated token); 21608 means the Twilio account is still a trial. Both show coaches "Texting codes is down on our side". Fix the keys in Netlify, re-add `TWILIO_VERIFY_SID`, redeploy, then test a code.

### Owner (All-Access Master)
- `netlify/security/owner.ts` decides who the owner is: confirmed Identity emails in its built-in list plus the `OWNER_EMAILS` env var (comma-separated). `api.ts` puts `owner` on the `Session`; `planOf` returns `TIERS.master` for the owner (no limits), `ensureProfile` keeps their `profiles.plan` at `master`, `choosePlan` refuses `master` and refuses the owner, and `spend` never cuts the owner off (it still counts). `master` is not in `PUBLIC_TIERS`. `session()` asks Identity's admin API whether the owner's email is confirmed when `getUser()` came back without the stamp (it falls back to bare token claims when Identity is unreachable); `GET /api/me` returns `ownerHint` to a listed address that was refused, so the reason is visible. Never gate owner powers on anything the browser sends.

### Owner console (`/admin`)
- `pages/Admin.tsx` (tabs in `pages/admin/`) is hidden from non-owners by `useOwner()`, but the real gate is `me.owner` on `/api/admin/*` (`adminRoute` in `api.ts`; anyone else gets the plain 404). Logic lives in `netlify/admin/` (`admin.ts` users, CSV, audit, `WATCH` thresholds for the abuse flags; `visits.ts` visitor counter). Owner views of one coach's data and every change go through `audit()` into the append-only `audit_log`.
- Signup history = Identity `admin.listUsers` ∪ `profiles` ∪ `account_ledger` (written by `deleteAccount`: email, hashed phone, no plays). `profiles.lastActiveAt` is touched by `ensureProfile` at most every five minutes.
- Recovery (`netlify/admin/recovery.ts`): the coach's own `DELETE` of a play or playbook first copies the row into `trash` (`keepInTrash`, 30 days, a playbook also keeps its member play ids); the owner opens a coach (`GET admin/users/:id`), restores from `trash` (`POST admin/trash/:id/restore`, optionally into another coach's account), downloads everything as JSON, or sets a plan (never `master`). Account deletion deliberately skips the trash (privacy promise) and only writes `account_ledger`.
- Visitor counter: `useVisitCounter` (`lib/visits.ts`) beacons `POST /api/visit` (public route, before the phone gate) per page view and every 30 s of visible time; rows in `visits` hold no IP, cookie or user id (visitor = hash of device id + day). DNT/GPC send nothing; the owner's own visits and `/admin` are skipped. This is separate from the three `track()` events.

- New coaches and the trial: with `TRIAL_SIGNUPS=on` a new account starts on `trial` (Coach tools for `TRIAL_DAYS`, `profiles.trialEndsAt`) and `planState()` in `api.ts` drops it to Sideline (`free`) when it ends; with it off, new accounts join as `beta` as before. One trial per person: `startTrial` folds the email (+tags, Gmail dots) and refuses throwaway domains and any email or phone seen in `trial_claims` or `account_ledger`; `verifiedPhone` takes the trial back if the number was already used or is internet-only (Twilio Lookup, fails open; `TRIAL_BLOCK_VOIP=off` skips it). The helpers are in `netlify/security/trial.ts`. While trials are on, `PUT /api/me/plan` only allows stepping down to Sideline (paid plans open with billing). Sideline caps: 15 drills and plays, 1 playbook (`gatePlaybook`, client and `POST /api/playbooks`), letter-page print with a watermark; plays over a cap are kept, not deleted.

### Export
`lib/export.tsx`: `PrintDiagram` / `sceneToSvg` is the source for every export and print preview. `lib/printLook.ts` frames a diagram for its printed size (`fit: "play"` crops to the players and routes; `weight` makes lines and tokens heavier, `"auto"` picks it from the size so a 1-inch wristband box doesn't print hairlines; auto tokens never drop below 0.09 in and print as plain dots under 0.11 in, and route tags/text grow to at least 5.5 pt). `frameScene` returns `ptPerUnit`, which turns on print-only drawing: white rings on tokens and white casings under routes (`NodeLayer print`), and a field that leaves off markings too small to read and keeps the lite LOS at half route weight. Zoom never cuts the play off (`keepPlay` slides or grows the box back over every player, curve control point, route tag and text). Yard lines in every field view (`yardLines` in `lib/field.tsx`) run every 5 yards out from the line of scrimmage and carry their distance, so a route's depth reads off the card; print field `"yards"` (the card default) draws just those lines and the LOS. `placeDiagram` draws into jsPDF as vector paths via `svg2pdf.js` (lazy-loaded) when `gateVector` allows, otherwise a PNG at the plan's DPI. `playsToPdf` and the export preview share `pdfSlots`. One-click styles are `EXPORT_PRESETS` in `ExportDialog.tsx`; a preset is just a partial set of the same settings, so add new ones there. Wristband cards and their page were removed in Phase 2c; the `wristband` print sizes, `noteWristband` and `wristbandBold` stay until 2d/2e. Drawings scale with the box: auto token and route weights are capped by the diagram's printed height (`autoWeight`), and `playBox` ignores anything dragged off the canvas so a stray node can't shrink the whole play. `PrintLook` also takes Playmaker-style `zoom`, `icons`, `lines` and `dots`. PowerPoint export is `lib/pptxExport.ts` (`pptxgenjs`, lazy-loaded); `lib/pptx.ts` is PowerPoint *import*. UI in `components/ExportDialog.tsx`.

### Field Controls
- One panel above the field (`components/FieldControls.tsx`, the Designer's "Field controls" button; "More" on phones) holds snap to grid (size), snap lines to players and its radius (the drawing bar's Snap), hash marks (high school, college, pro, none), yard-line contrast (soft, standard, high). `lib/fieldPrefs.ts` keeps them in `laxvault.field.v1` (per browser, like the other prefs); `FieldBackground` reads hashes and contrast from it unless given props, so the canvas, thumbnails, Run play and every export match. Flag views never draw hashes; the grid never prints. Export starts with rule lines on when they're on in the Designer.

### Practice planner
- "Run live" opens live practice mode (`/practice/live`, see Phase 3f above).
- `/practice` (`pages/Practice.tsx`, `lib/practice.ts`): one script per browser (`laxvault.practice.v1`) of timed periods, each with Vault plays (single or a whole playbook). ### Copy style
- `lib/styleCopy.ts`: Ctrl+Alt+C copies one element's look (colors, weight, size; never labels, points, first read or tags), Ctrl+Alt+V (or "Paste style" in the right-click menu) puts it on every selected element of the same kind and skips locked ones. The copied style is kept in `laxvault.styleclip.v1`.

### Routing and shell
- `src/App.tsx` defines routes; `/build/:id` and `/grid/:id` are deep-linkable, so `netlify.toml` rewrites `/*` → `/index.html`. Placeholder routes come from `COMING_SOON` in `pages/ComingSoon.tsx`.
- When adding a route, also add it to `TITLES` and `NAMES` in `App.tsx` — `RouteChrome` sets `document.title` and announces the page via a live region.
- Signed-in pages wrap content in `components/Shell.tsx` (the shared side menu). The menu's tool list is `PLAYBOOK_NAV` in `lib/nav.ts`; the home page's "Every tool, one click away" grid renders the same list, so add a tool there once and both pick it up.
- Auth UI state: `lib/auth.tsx` (`AuthProvider`/`useAuth`). If Identity isn't enabled, `available` is false and the app stays local-only. Map Identity errors through `authMessage()`, never show raw error text.

## Conventions

- **Styling:** plain CSS. Design tokens live only in `src/styles/tokens.css`; `global.css` consumes them. **The LaxVault brand preview (palette B app, palette H live mode) is the source of truth for color**; type families are inherited from the football app. Change a value in tokens, not in component styles. Fonts: Saira Condensed, Barlow, IBM Plex Mono (Google Fonts, loaded in `index.html`).
- **Colors in scene data** are hex constants in `types.ts` (`PALETTE`, `FIRST_READ`, `STROKE_WEIGHTS`) and `presets.ts` (position colors: Q black · C cyan · X blue · Y red · Z green · H orange · S light purple), since they are serialised into saved plays and exports.
- **Copy:** user-facing text speaks to "coach", is specific and action-oriented, and never leaks raw library/server errors. `docs/copy-audit.md` records the standard and past fixes.
- **Accessibility:** WCAG 2.1 AA. Reuse `Modal` (focus trap, Escape, `aria-labelledby`), `Tooltip` (`aria-describedby`) and `Panel` (`aria-expanded`) rather than building new ones. `docs/accessibility.md` is the record of what was fixed and why.
- **Analytics:** only five events exist on purpose (`play_created`, `practice_opened`, `play_exported`, `plan_built`, `live_started`) — don't add more without a reason.
- **CSP:** `netlify.toml` sets a strict Content-Security-Policy (`script-src 'self'`, `connect-src 'self'`, fonts only from Google). New third-party scripts, fetches or fonts must be added there or they'll be blocked in production.
- `NETLIFY_NEXT_PLUGIN_SKIP=true` in `netlify.toml` is intentional (a leftover account-level Next.js plugin); keep it.
- Work lands in small phase-labelled PRs (e.g. "Phase 1: …") merged into `main`.
